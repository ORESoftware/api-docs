# Web page Lambda contract — draft

> **Scope: `*-web-server.rs` / `*-admin-web-server.rs` only. This is not the API-server Lambda/RPC contract.**

A browser URL is owned by its authored page folder:

```text
src/pages/x/y/z/
  page.rs      # authored page
  gen.rs       # optional authored build-time static enumeration
  lambda.rs    # generated deployment entrypoint; never authored
```

`page.rs` is the only routing authority. `lambda.rs` is a deployment projection of that page; it never creates an RPC operation, route key, or second path definition.

## Reconciled architecture

The coordinated draft set is:

| PR | Owns |
| --- | --- |
| `api-docs#177` | page/API boundary and page docs/manifest direction |
| `api-docs#176` | generated page ABI, sibling `lambda.rs`, shared response finalization |
| `ores-stack#69` | repository-role admission, web manifest/docs/deployment IR |
| `ores-stack#68` | `ores-stack web lambda` materialization/build/package |
| `ores-lambdas-template#35` | provider HTTP lifecycle and middleware |

The settled rules are:

1. `lambda.rs` is a generated sibling of `page.rs`.
2. `api-docs` owns the one generated marker:
   `// @generated by ores-api-docs for a *-web-server.rs page; DO NOT EDIT.`
3. All orchestration lives under `ores-stack web ...`; web pages do not use the API/RPC Lambda command surface.
4. Non-source outputs live under `generated/web/`, including manifests, docs and per-unit Cargo manifests.
5. Route discovery is build-time. No serving process walks the filesystem to find pages.
6. Page modules remain private. Cross-crate Lambda access uses generated, digest-suffixed trampolines.
7. Application state, page invocation and response finalization are explicit typed ABIs.
8. One page per Lambda is the first supported deployment model. Route grouping remains reserved until parity is proven.
9. A page manifest may record `rpc_dependencies[]` that a page calls, but a page never acquires RPC-operation identity.
10. Generated Lambda build units are isolated Cargo workspace roots and build from committed/pinned locks with `--locked`.

## Public web-library ABI

A web-server library exporting generated page Lambda support provides:

```rust
pub mod ores_pages {
    include!(concat!(env!("OUT_DIR"), "/ores_pages.rs"));
}

pub fn ores_page_lambda_state() -> ores_api_docs_client::PageLambdaStateFuture {
    // Build exactly the application state used by the standalone server.
    // Called once per provider cold start.
    # todo!()
}
```

The generated `ores_pages` module keeps each source `page.rs` module private. It exports two `#[doc(hidden)]` functions per page:

```text
__ores_invoke_page_<readable-stem>_<sha256(source-path)/16>
__ores_finalize_page_<readable-stem>_<sha256(source-path)/16>
```

The digest suffix is mandatory because the readable normalization is lossy (`a-b` and `a_b` otherwise collide).

The functions are compile-time asserted as:

```rust
ores_api_docs_client::PageFn
ore_api_docs_client::PageFinalizeFn // conceptual spelling; actual crate path is ores_api_docs_client
```

and the state constructor is asserted as:

```rust
ores_api_docs_client::PageLambdaStateFn
```

In generated source the actual type is `::ores_api_docs_client::PageFinalizeFn`; the shortened line above is documentation only.

## Shared response finalization

Response finalization is now an explicit, Axum-free client ABI in `api-docs#176`:

```rust
pub struct PageResponseAssets<'a> {
    pub css_href: Option<&'a str>,
    pub wasm_sha256: Option<&'a str>,
    pub js_src: Option<&'a str>,
}

pub struct PageResponseRequestHints<'a> {
    pub wasm_have: Option<&'a str>,
    pub dev_reload_script: Option<&'a str>,
}

pub struct FinalizedPageResponse {
    pub status: u16,
    pub headers: Vec<(String, String)>,
    pub body: Vec<u8>,
}

pub type PageFinalizeFn =
    for<'a> fn(PageResult, PageResponseRequestHints<'a>) -> FinalizedPageResponse;
```

`page_router_glue` emits one public hidden finalizer trampoline per page. That trampoline closes over the **same admitted `PageBuildRoute` asset metadata** used by the standalone Axum build: CSS public path, finalized WASM digest and JS public path.

Both hosts therefore call the exact same generated finalizer:

```text
standalone Axum
  page.rs -> PageResult
          -> per-page PageFinalizeFn
          -> FinalizedPageResponse
          -> Axum Response

AWS/GCP page Lambda
  page.rs -> PageResult
          -> the same per-page PageFinalizeFn
          -> FinalizedPageResponse
          -> provider envelope
```

The shared finalizer owns HTML status/content type, CSS injection, WASM bootstrap suppression/injection, safe loopback-only dev reload injection, and stable render-error responses. Render errors are non-cacheable and do not reflect `PageError` details to the browser.

Provider runtimes must not rediscover CSS/WASM metadata or duplicate HTML mutation logic.

## Generated `lambda.rs`

Conceptually one generated entrypoint looks like:

```rust
// @generated by ores-api-docs for a *-web-server.rs page; DO NOT EDIT.
// WEB SERVER PAGE LAMBDA ONLY — not an API-server RPC adapter.

pub const ORES_PAGE_SOURCE: &str = "src/pages/x/y/z/page.rs";
pub const ORES_PAGE_ROUTE: &str = "/x/y/z";
pub const ORES_PAGE_AXUM_PATHS: &[&str] = &["/x/y/z"];

const __ORES_PAGE: ::ores_api_docs_client::PageFn =
    ::ores_web_app::ores_pages::__ores_invoke_page_<stem>_<digest>;
const __ORES_PAGE_FINALIZE: ::ores_api_docs_client::PageFinalizeFn =
    ::ores_web_app::ores_pages::__ores_finalize_page_<stem>_<digest>;
const __ORES_PAGE_STATE: ::ores_api_docs_client::PageLambdaStateFn =
    ::ores_web_app::ores_page_lambda_state;

async fn __ores_handle_page(
    state: ::ores_api_docs_client::PageState,
    request: ::ores_page_lambda_runtime::PageHttpRequest,
) -> Result<
    ::ores_page_lambda_runtime::PageHttpResponse,
    ::ores_page_lambda_runtime::RuntimeError,
> {
    ::ores_page_lambda_runtime::invoke_page(
        request,
        state,
        ORES_PAGE_ROUTE,
        ORES_PAGE_AXUM_PATHS,
        __ORES_PAGE,
        __ORES_PAGE_FINALIZE,
    )
    .await
}
```

The generated source contains mutually exclusive AWS/GCP feature-gated `main` functions. Exactly one provider feature must be enabled.

`lambda.rs` never mounts `page.rs` with `#[path]`. Doing so from a bin crate would change the meaning of every `crate::...` path in authored page code. The web-server library is instead aliased to the stable generated dependency name `ores_web_app`.

## Provider-neutral HTTP boundary

The provider runtime normalizes requests before page invocation. The first contract must preserve:

- GET/HEAD admission and explicit rejection of unsupported methods;
- raw URI/path/query semantics;
- canonical lowercase, multi-valued request headers;
- bounded decoded body bytes;
- trusted provider/ingress provenance separate from client headers;
- route params extracted with the same filesystem grammar as standalone Axum;
- request/deadline/trace metadata;
- auth/session middleware appropriate to the web or admin-web realm.

Provider-specific response conversion happens **after** the shared `PageFinalizeFn`.

## Build/package contract

`ores-stack` owns materialization and packaging:

```text
ores-stack web lambda plan
ores-stack web lambda sync
ores-stack web lambda sync --check
ores-stack web lambda build --provider aws|gcp
ores-stack web lambda package --provider aws|gcp
```

`sync` writes the generated sibling `lambda.rs`. `--check` is read-only and fails on missing, stale, unmarked, hand-edited or symlinked generated files.

Each build unit lives at:

```text
generated/web/lambda/<unit>/
  Cargo.toml
  Cargo.lock
  build-metadata.json
```

The generated manifest is its own `[workspace]` root, aliases the product web library to `ores_web_app`, aliases the org-specific provider package to `ores_page_lambda_runtime`, and points `[[bin]]` at the sibling `src/pages/.../lambda.rs`.

Release builds use immutable dependency revisions and `--locked`. Generated deployment receipts bind at least the source SHA, page-manifest digest, page source SHA, generated Lambda SHA, finalized asset digest, provider, architecture, runtime/toolchain and package checksum.

## Compile proof

`rust/tests/page_lambda_compile_fixture.rs` builds the intended topology, not a string approximation:

- private page module;
- authored page using `crate::...` paths;
- application state passed through `PageLambdaStateFn`;
- full `page_router_glue` output, including the per-page `PageFinalizeFn`;
- generated `lambda.rs` as a separate bin crate;
- stable aliases for web app and provider runtime;
- an isolated generated `[workspace]`;
- AWS and GCP feature builds;
- both/neither provider features rejected.

The fixture executes the generated binary and proves the page result flows through shared finalization.

## Security invariants

- Generated source contains no provider credentials or mutable deployment secrets.
- Client headers cannot manufacture trusted provider identity.
- Auth/middleware rejection occurs before page invocation.
- `PageError` details are for server-side telemetry and are not rendered to browsers.
- A web page does not gain database write authority merely because it is deployed as a Lambda.
- `gen.rs` remains build-time only and is never exposed as a request handler.

3. Land `ores-stack web lambda sync --check` and generated build units.
